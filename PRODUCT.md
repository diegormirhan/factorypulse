# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated for this build: Python 3.12, scikit-learn, FastAPI, and a dependency-free HTML/CSS/JavaScript frontend. The choice keeps model training and inference local while making the complete workflow easy to run and review.

## Users

Assumed primary user: a reliability or maintenance analyst reviewing one machine at a time or scoring a CSV batch before planning inspections.

Assumed portfolio audience: ML and data-science recruiters or engineering interviewers evaluating the quality of the end-to-end system.

## Product Purpose

FactoryPulse estimates machine-failure risk from operating measurements, makes the risk drivers inspectable, and detects distribution drift between reference and incoming data. Success means a reviewer can reproduce training, inspect evaluation evidence, run predictions through an API or dashboard, and understand why the system raised an alert.

## Positioning

The product connects a leakage-safe tabular ML pipeline to cost-aware threshold selection, deterministic local explanations, batch scoring, and drift monitoring in one offline, auditable workflow.

## Operating Context

The product is evaluated locally with the public AI4I 2020 Predictive Maintenance dataset. Its dashboard represents a maintenance operations workstation. All machine records and operational summaries included with the repository are demonstration data.

## Capabilities and Constraints

- Fully local training and inference; no API keys or cloud services.
- Reproducible data acquisition, validation, model comparison, evaluation, and artifact generation.
- Single-machine and CSV batch prediction.
- Global and per-prediction explanations without an LLM.
- Reference-versus-current feature drift report.
- Failure-mode columns are excluded from predictors because they reveal the target.
- The model is educational portfolio software, not a certified industrial safety system.

## Brand Commitments

FactoryPulse is the working product name. Voice is direct, operational, and evidence-led. The interface must not invent customers, deployments, savings, or production claims.

## Evidence on Hand

- UCI AI4I 2020 Predictive Maintenance dataset and its published feature definitions.
- Reproducible evaluation metrics and artifacts generated by this repository.
- No customer testimonials, production deployment evidence, or real maintenance records are available and none may be fabricated.

## Product Principles

- Make every model decision traceable to data, configuration, and saved evidence.
- Prefer deterministic statistical and ML methods where they solve the problem.
- Optimize the alert threshold for the declared maintenance cost trade-off, not for accuracy.
- Keep the complete workflow runnable on a developer laptop.
- Separate domain logic, model code, I/O, and presentation so each can be tested independently.

## Accessibility & Inclusion

Assumed target: WCAG 2.2 AA for keyboard access, focus visibility, contrast, reduced motion, and non-color-only status communication.
